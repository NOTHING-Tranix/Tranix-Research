**Research Topic:** LoadProof — Website Design and MVP Implementation

## 1. What I Researched

I explored how the proposed LoadProof concept can be developed as a simple web application to manage truck trip details, freight payments, supporting documents, warehouse timelines, and deduction-related alerts.

I also identified the main website pages, technologies required, and the development steps for building the initial Minimum Viable Product (MVP).

## 2. What I Found

**Finding 1: User Login and Role Selection**

The website can support different user roles, such as truck owners, drivers, transport offices, and brokers. To keep the first version simple, development can initially focus on truck owners and transport offices.

**Finding 2: Dashboard and Main Features**

The dashboard can contain separate sections for:
- My Trips — Create and view trip records.
- Documents — Store freight agreements, invoices, and proof of delivery.
- Payments — Track total freight, advance, balance, and deductions.
- Trip Timeline — Record warehouse arrival, unloading, and other relevant events.
- Alerts — Highlight missing documents, overdue payments, and deductions requiring review.

**Finding 3: Warehouse Storage Charge Verification**

For example, if the agreed freight is ₹50,000 and the advance payment is ₹10,000, the initial remaining balance is ₹40,000. If a ₹5,000 storage charge is later claimed, the system can check whether supporting evidence and relevant trip records are available.

If the required proof is missing, the system can display a **“Needs Review”** alert instead of automatically accepting or rejecting the deduction.

**Finding 4: Proposed Technology Stack**

The initial web application can be developed using:

- HTML, CSS, and Bootstrap for the user interface.
- JavaScript for form validation, calculations, and interactive alerts.
- Node.js and Express.js for backend operations.
- MongoDB for storing user, trip, payment, and related records.

**Finding 5: Step-by-Step MVP Development**

The initial development sequence can be:

1. Create the login page.
2. Design the dashboard and navigation sidebar.
3. Build the Create Trip form.
4. Connect the backend and MongoDB to save trip details.
5. Implement payment tracking and balance calculations.
6. Add document management and warehouse timeline records.
7. Implement missing-proof and payment-delay alerts.

**Finding 6: Keep the First Version Simple**

Advanced features such as AI-based analysis, live truck tracking, and payment gateway integration can be postponed. The first priority is to ensure that the core trip, payment, and evidence-management workflow works correctly.

## 3. My Thoughts

I think developing LoadProof as a web application is a practical starting point. Instead of implementing every feature at once, we can first build a basic MVP with trip creation, payment tracking, document records, and warehouse timeline management.

The important part is to connect the agreed trip terms, warehouse events, supporting evidence, and final deductions in one place. The system should identify missing information and issues requiring review, rather than automatically deciding who is responsible.

After building and testing the basic workflow, the next step would be to evaluate its usefulness with truck owners and transport office users.

## 4. Questions / Doubts

1. Should the first MVP support only truck owners and transport offices?
2. What minimum documents should be required for each trip?
3. How should warehouse arrival and unloading times be recorded and verified?
4. Should payment deductions require a reason and supporting document before they can be marked as verified?
5. How can access to sensitive trip and payment records be restricted by user role?
6. Which features should be prioritised for the first working prototype?
